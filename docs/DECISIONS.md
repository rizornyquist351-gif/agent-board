## 已决定

### D1 · 2026-11-23 · 定位为个人工具，不做商业化
原因：同类项目中最火的 Vibe Kanban（约 2.88 万星、每天数千用户）因找不到商业模式于 2026 年 4 月停止商业运营。

### D2 · 2026-11-23 · 分阶段推进，每阶段单独可用
原因：个人项目最常见的死因是范围膨胀、没有定义"做完"。每个阶段有明确完成标准，可以随时停下。

### D3 · 2026-11-23 · 先只支持 Claude Code，底层优先复用 Agent Teams 共享任务列表
原因：官方已提供自主认领、组长分配、任务依赖（实验性功能，需设置 `CLAUDE_CODE_EXPERIMENTAL_AGENT_TEAMS=1`），不必重造。

### D4 · 2026-11-23 · 发布任务必须结构化（目标 / 产出格式 / 工具与资料来源 / 任务边界 + 验收标准）
原因：Anthropic 的多 agent 调研系统实践表明，任务描述模糊会导致重复劳动和遗漏；MAST 研究显示"结果验证不足"是三大类失败之一。

### D5 · 2026-11-23 · 开发任务必须有 WIP 上限和人工审核
原因：多份实践经验一致指出，人工审核是真正的瓶颈；并行开发即使隔离也会冲突。

### D6 · 2026-11-23 · 技术栈：TypeScript 全栈（后端 Node.js，前端 React + Vite）
原因：用户选择。前后端同一种语言；同类项目大多用这一套，资料多。

### D7 · 2026-11-23 · 部署：本地运行
原因：用户选择。在跑 agent 的机器上启动，浏览器打开 localhost；最简单，第 0 阶段足够。

### D8 · 2026-11-23 · 用户确认 CLAUDE.md 的目标与「明确不做」清单
范围以 CLAUDE.md 为准，计划外的想法记进 ROADMAP「以后再说」。

### D9 · 2026-11-23 · 数据来源：直接读 Claude Code 任务文件，不另建存储
监听并读取 `~/.claude/tasks/*/` 下的任务 JSON，团队成员读 `~/.claude/teams/*/config.json`；读取逻辑集中在一个适配器模块，容错处理。原因：只读可视化不需要自己的数据库；格式简单（见 RESEARCH.md 第五节）。用户确认。

### D10 · 2026-11-23 · 实时更新用 SSE
原因：第 0 阶段只需要服务器 → 浏览器单向推送，SSE 比 WebSocket 简单，浏览器自带断线重连。第 1 阶段发布任务走普通 HTTP POST。用户确认。

### D11 · 2026-11-23 · 方向调整为"许愿式"（部分取代 D3、D4 的做法）
用户提出：使用时越傻瓜越好，一句话说要干什么，不用多配置，直观看到状态。
- 用户一句话许愿 → **规划 agent** 拆任务并自动补全 D4 要求的各项（目标、产出、边界、验收标准），用户只需确认。D4 的道理保留，填写的人从用户变成规划 agent。
- **看板自己启动并调度 agent**（Claude Code 非交互模式 `claude -p`），不再依赖 agent 自行认领。只有一个派活方，原子认领问题自然消失。取代 D3 中"底层复用 Agent Teams 共享任务列表"。
- 路线改为：第 1 阶段单 agent 跑通许愿闭环 → 第 2 阶段多 agent 并行 → 第 3 阶段零配置。
- 第 0 阶段随之验收通过，其看板界面和数据读取保留复用。

### D12 · 2026-11-23 · agent 自主程度：独立分支里自主干活，合并须用户通过
用户选择。每次许愿在独立 git 分支 / worktree 中进行，agent 可自动改文件、跑命令，不打扰用户；合并、推送必须经用户点"通过"。

### D13 · 2026-11-23 · 本地接口的安全措施
看板能启动会改文件的 agent，必须防止别的网站替用户"许愿"。服务器只监听 127.0.0.1；拒绝 Host 不是本机（防 DNS 重绑定）或 Origin 来自其他网站的请求；写操作必须是 JSON 请求（普通表单无法跨站发送）。

### D14 · 2026-11-23 · 执行细节
- 执行 agent 默认权限模式 `auto`（实测在 `-p` 模式下可自动改文件、跑命令），可用环境变量改。
- 规划 agent 只给只读工具 Read/Glob/Grep（RESEARCH.md 第六节：否则会超预算）。
- worktree 放在 `~/.agent-board/worktrees/{项目名}-{路径哈希}/`，**不放在项目里**：否则用户项目的测试 / 构建工具会扫到 worktree 里的副本。
- 状态文件放在 `项目/.agent-board/state.json`，通过 `.git/info/exclude` 忽略，不改用户的 `.gitignore`。
- 每个任务完成后自动提交一次；合并用 `--no-ff`，用户能在 git 历史里看到每次许愿。
- 看板只依赖 Runner 接口；另有不花钱的假 Runner，用于测试和演示模式（`AGENT_BOARD_FAKE=1`）。
