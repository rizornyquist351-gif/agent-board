## 第 1 阶段：许愿最小闭环（单 agent）

**完成标准**：在网页上用一句话许愿 → 看到自动拆出的任务并点"开始" → 一个 agent 在独立分支里按顺序完成 → 页面实时显示它在做什么 → 用户点"通过"后合并到主分支（或点"打回"丢弃）。

- [ ] 项目设置：启动时指定要干活的项目目录（git 仓库），状态保存在该项目的 `.agent-board/` 下
- [ ] 许愿输入框 + 规划 agent：一句话 → 结构化任务清单（每个任务含目标、产出、边界、验收标准；D4）
- [ ] 确认页：用户看拆出的任务，可删改，点"开始"
- [ ] 执行器：为这次许愿建独立分支 / worktree，按顺序给 agent 派任务，记录每一步
- [ ] 实时显示：用大白话显示 agent 当前在干什么（读文件、改文件、运行命令…）
- [ ] 失败处理：某个任务失败时停下并醒目提示，可重试或跳过
- [ ] 审核：全部完成后显示改动摘要，用户点"通过"（合并）或"打回"（丢弃分支）
- [ ] 费用上限：每次运行带默认上限

## 第 2 阶段：多 agent 并行（预计 1 周）

- 角色分工：调研员（产出报告）、开发者（产出改动）
- 同时运行多个 agent，各自独立 worktree；WIP 上限
- 规划时标出任务依赖，可并行的并行，有依赖的排队
- 每个任务单独审核
