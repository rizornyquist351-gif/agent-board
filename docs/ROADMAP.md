## 第 1 阶段：许愿最小闭环（单 agent）

**完成标准**：在网页上用一句话许愿 → 看到自动拆出的任务并点"开始" → 一个 agent 在独立分支里按顺序完成 → 页面实时显示它在做什么 → 用户点"通过"后合并到主分支（或点"打回"丢弃）。

- [x] 项目设置：启动时指定项目目录（`npm start -- 路径`），状态保存在 `项目/.agent-board/state.json`（git 自动忽略）
- [x] 许愿输入框 + 规划 agent：一句话 → 结构化任务清单（每个任务含目标、产出、边界、验收标准；D4）
- [x] 确认页：用户看拆出的任务，可删改，点"开始"
- [x] 执行器：为这次许愿建独立分支 / worktree（放在项目之外，D14），按顺序派任务，每个任务一个提交
- [x] 实时显示：用大白话显示 agent 当前在干什么，附过程记录
- [x] 失败处理：失败时停下并醒目提示，可重试 / 跳过 / 打回；也可随时手动停止
- [x] 审核：显示 agent 的总结、改动文件、完整 diff；"通过"合并（有未提交改动时拒绝）/ "打回"丢弃
- [x] 费用上限：规划 $0.5、每个任务 $2（可配置），界面显示花费

## 第 2 阶段：多 agent 并行（预计 1 周）

- 角色分工：调研员（产出报告）、开发者（产出改动）
- 同时运行多个 agent，各自独立 worktree；WIP 上限
- 规划时标出任务依赖，可并行的并行，有依赖的排队
- 每个任务单独审核
